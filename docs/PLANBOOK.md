# План пачки в Excel с весами источников и модели (`luna planbook`)

Генератор собирает книгу Excel со структурой ваших прежних планов из ChatGPT:
дашборд, сигилы и таланты, лимбы, украшения, приоритет прокачки украшений, карты прелестей,
питомцы, руны и оружие принцессы. Разница в том, что каждая рекомендация получена из «голосов»
источников с явными весами и формулами. Веса можно менять прямо в Excel.

```bash
python -m luna collect-appmedia          # обновить японские билды AppMedia (кэш data/cache/appmedia)
python -m luna planbook                  # книга reports/planbook/Luna_planbook_<дата>.xlsx
python -m luna planbook --no-model       # без симулятора (быстро)
python -m luna planbook --team data/user/teams/main.json --model-n 1000
```

lunafantasy.ru одинаков для всех героинь, поэтому он не считается рекомендацией.

## Формулы

* **Вес голоса** = W источника × W группы × W сопоставления × 1/(1+γ·(позиция−1)) × рейтинг × свежесть.
  * W группы: основная рекомендация 1.0, место в списке 0.8, кандидат 0.6, «не рекомендуется» −0.6.
  * W сопоставления: подтверждено 1.0, перевод по смыслу 0.95, гипотеза 0.75, соответствие не найдено 0.6.
  * Рейтинг: ★ из ★ максимума, x/5 или 1.
  * Свежесть = max(0.3; 0.5^(возраст/365 дней)).
* **Консенсус** — сумма весов голосов, нормированная к лучшему кандидату героини в категории.
* **Модель** — нормированный эффект симулятора. Учитываются только значимые эффекты: 95% доверительный интервал не пересекает 0.
* **Итог** = (α·Консенсус + β·Модель)/(α+β), где α = 0.75, β = 0.25. Если модельного значения нет, Итог = Консенсус.
* **Ранг** в категории считается по Итогу; при равенстве выше стоит кандидат с меньшим номером строки.
  Python-реализация (`luna/planbook/score.py`) совпадает с формулами книги. Тест сверяет их после пересчёта в LibreOffice.
* **Назначения с ограничениями** считает CP-SAT при генерации книги:
  * карты прелестей — одна на деву, без повторов в составе;
  * питомцы — 4 на деву, у каждого питомца лимит связей по редкости. Этот лимит взят из планов ChatGPT и **не подтверждён**.

## Модель (симулятор, не реальный винрейт)

Используется парный Монте-Карло с общими случайными числами: моя команда с изменением играет против неизменённой.

* **Бонус 2 частей лимба** — к одной героине добавляется +X% стата. Бонус 4 частей пока не закодирован.
* **Вклад кита** — навыки героини заменяются обычной атакой.
* **Метрика:** победа = 1, поражение = 0. Ничья по лимиту раундов = 0.5 + 0.5 × (доля ОЗ A − доля ОЗ B).
* **Мяоинь без панели оператора:** её статы оценены как образец JP 350 ур. × медиана отношения
  «панель / образец» у остальных героинь.

**Найдено при проверке.** В зеркальном бою баф команды +5% СКР от Иллюсии *снижал* модельный балл
(0.65 → 0.82 без бафа). Это артефакт темпа зеркального матча и шума, а не механика игры. Поэтому
в веса попадают только значимые эффекты, а вес модели по умолчанию небольшой.

## Сопоставление имён

Японские термины переводятся в русские названия клиента (`luna/planbook/terms.py`), и у каждого
соответствия есть статус. Спорные случаи вынесены на лист «Сопоставление_JP_RU» с жёлтой колонкой
для решения оператора:
* 迅速 — «Ловкость» или «Быстрота»/«СКР»;
* 庇護 — «Покровительство» или «Иммунитет к урону»;
* 強靭 — «Упорство» или «Стойкость»;
* 神護 — «Святое благословение» или «Божественная защита»;
* 滅魂 — «Похититель душ»?
* а также питомцы с японскими названиями.

## Ограничения

* Страницы AppMedia в основном обновлялись в мае–июне 2025 года, поэтому множитель свежести у них низкий.
  Это можно изменить параметром `half_life`.
* Синергия пар в модели не оценивается: для этого нужны закодированные киты всех героинь.
* Модель покрывает только героинь с закодированными навыками (основной состав оператора).
